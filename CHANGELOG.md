# Что нового в RDstreamer

Все версии RDstreamer по порядку, от новых к старым. Скачать образ или пакет:
[Releases](https://github.com/radievdmytro/RDstreamer/releases).

Обновление: **System → Updates** в веб-интерфейсе (начиная с 1.3 устройство
само находит, скачивает и проверяет подписанные релизы RDstreamer). Новая
установка: записать `.img.xz` на microSD через Raspberry Pi Imager (**Use custom**).

---

## Следующая версия (в работе)

- **Имя RDstreamer везде, где его видно.** Сообщения команд в терминале,
  описание службы, установщик, имя источника OMT, вкладка «About», имя файла
  с резервной копией настроек и логин для менеджера паролей теперь говорят
  RDstreamer. Внутренние имена (команда `ystreamer`, служба `ystreamer`,
  папки `/etc/ystreamer` и т. п.) оставлены как есть: на них опираются
  обновления уже установленных устройств.
- **Сообщить об ошибке** (System → About) открывает задачу в репозитории
  RDstreamer, а не в исходном проекте.
- **README, CHANGELOG, CONTRIBUTING и шаблоны задач** переписаны под
  RDstreamer.

## 1.22 · Processing в меню у зрителей, крупный адрес с копированием

- **Переключатель Processing у гостей.** В меню просмотра (кнопка с ползунками
  справа вверху) рядом с Quality и Connection — **Processing: On / Off**. По
  умолчанию включён; выбор каждого зрителя запоминается в его браузере.
- Переключатель **Processing · in browsers** в окне Watch у администратора
  задаёт значение по умолчанию для всех зрителей.
- Данные для покраски (LUT и Dewarp) приходят зрителю всегда, когда они
  включены на HDMI, поэтому зритель может включить обработку сам, даже если по
  умолчанию она выключена.
- **Окно входа в Wi-Fi** (появляется само на телефонах и компьютерах): адрес
  показан крупно по центру, под ним большая кнопка **Copy address**; после
  нажатия — «Copied — now paste it in the browser». Над адресом короткая
  инструкция: на iPhone — закрыть окно (Done или ✓) и вставить адрес в Safari,
  на Android — вставить в Chrome (там же кнопка «Open in browser»).

## 1.21 · Браузеры красят сами, исправлены цвета обработки на Pi

- **Обработка для браузеров на Pi убрана.** Pi всегда отдаёт браузерам
  исходную картинку, а LUT и Dewarp накладывает видеокарта браузера (WebGL) —
  тем же шейдером, что и на HDMI. Pi не тратит силы на второй кодировщик.
- **Синие лица в обработанных трансляциях.** Блок обработки изображения Pi
  принимает RGBA с переставленными красным и синим каналами; теперь шейдер
  отдаёт их в нужном порядке. Касается RTSP / SRT / RTMP / UDP с включённым
  Processing.
- Подсказки на Display → Stabilisation: стабилизация есть на HDMI и в
  трансляциях с Processing, в браузере её нет.

## 1.20 · Покраска в браузере или на Pi

- Для просмотра в браузере появился выбор **Graded in: Browser / Pi**
  (в 1.21 оставлен только Browser):
  - **Browser** — Pi отдаёт оригинал, каждый браузер сам накладывает LUT и
    Dewarp, без нагрузки на Pi;
  - **Pi** — Pi красит, стабилизирует и заново кодирует поток.
- Текстура LUT (`/api/display/look/atlas`) доступна без входа, чтобы её могли
  загрузить гости.

## 1.19 · Без двойного LUT в превью, яркость обработки как на HDMI

- **Двойная покраска.** Превью на Display → Image красит картинку в браузере
  само; когда браузеры уже получали обработанный поток, LUT накладывался
  второй раз — картинка темнела и тормозила. Превью теперь всегда берёт
  оригинал с очков (`?source=original`).
- **Обработанная картинка темнее, чем на HDMI.** Блок обработки изображения
  ждёт RGB в «видео-уровнях» (16–235), а получал полный диапазон — тени
  проваливались. Теперь шейдер отдаёт ему нужный диапазон.

## 1.18 · Информация на заставке: скрыть или компактно в углу

- **Display → Background video → Show connection details over the video**:
  можно убрать с заставки с видео статус, адреса и данные Wi-Fi — на HDMI
  остаётся только видео.
- **Display → Splash screen → Details layout**:
  - **Band at the bottom** — как раньше, полоса внизу крупным шрифтом;
  - **Compact, in a corner** — небольшой полупрозрачный блок, по строке на
    подключение, в выбранном углу (↖ ↗ ↙ ↘).
- Компактный вид работает и поверх своей картинки-заставки.

## 1.17 · Processing: переключатель на Watch и в каждой трансляции, статус, запасные режимы

- Переключатель **Processing** стоит в самом верху карточки каждой
  трансляции (RTSP, SRT, RTMP, UDP, Browser viewing), а в окне Watch рядом с
  плеером — блок **Processing** (срабатывает сразу, без Save).
- **Статус обработки** под каждым переключателем: Running / Starting / Failed /
  Not running и причина (например, «LUT, Dewarp and Stabilisation are all
  off»). Источник — `/api/processing`.
- **Запасные режимы кодирования:** без копирования → с копированием → 720p с
  конвертацией на процессоре. Следующий пробуется после ошибки или если 5 с
  на выходе ничего нет; если не сработал ни один, уходит оригинал.
- **Исправлено возможное зависание** при остановке обработки (последние кадры
  ждали блокировку, которую держала остановка).

## 1.16 · Стабилизация v2, обработка по трансляциям, режим с задержкой

- **Стабилизация v2** (Display → Image → Stabilisation):
  - коррекция делается в той же геометрии, где измеряется движение (до
    выпрямления Dewarp) — края больше не «плывут желе»;
  - картинка только равномерно приближается, без растягивания;
  - отдельные ползунки **Shake** (тряска), **Horizon** (горизонт; 0 — не
    трогать) и **Zoom** (запас для сдвига, +2…+30 %);
  - неправдоподобные рывки не дёргают картинку — стабилизация начинается
    заново;
  - движение по горизонтали оценивается по верхней и нижней половинам кадра.
- **Look ahead — режим с задержкой** (Live / 0.25 / 0.5 / 1 с): картинка
  показывается позже, а каждый кадр сглаживается с учётом следующих — ровнее,
  и панорамы начинаются без отставания. Кадры на время задержки хранятся в
  памяти видеоядра в NV12. Для полёта — Live.
- **Processing для каждой трансляции отдельно** вместо одного общего
  переключателя: RTSP, SRT, RTMP, UDP — по умолчанию оригинал (плоская
  картинка для покраски в OBS), браузеры — с обработкой. Запись всегда
  оригинал. Переключение не перезапускает сервер трансляции.

## 1.15 · Стабилизация, обработка в трансляциях

- **Стабилизация картинки** на Pi: каждый кадр в 160×90 сравнивается с
  предыдущим (суммы по строкам и столбцам, крен — по сдвигу левой и правой
  сторон), путь камеры сглаживается, панорамы пропускаются, шейдер
  возвращает кадр на место. Display → Image → Stabilisation.
- **Обработанная картинка в трансляциях:** кадры проходят тот же шейдер
  (LUT, Dewarp, стабилизация) и аппаратный кодировщик (1080p30, 8 Мбит/с,
  ключевой кадр раз в секунду). Пока он работает, RTSP, SRT, RTMP, UDP и
  браузеры получают его; через секунду после остановки — снова оригинал.

## 1.14 · Выход из окна входа в браузер

- Apple не даёт окну входа в Wi-Fi открыть Safari, поэтому на iPhone
  страница прямо говорит об этом и предлагает скопировать адрес с подсказкой,
  куда нажать. Android по-прежнему открывает браузер сам, на компьютере
  (macOS) — ссылка «Open in browser» и копирование как запасной вариант.

## 1.13 · Просмотр при подключении, кнопка «Открыть в браузере»

- На любой запрос проверки интернета устройство отвечает страницей просмотра
  — окно входа больше не показывает «Success» вместо видео.
- На телефонах — полоса с адресом, кнопкой Copy и «Open in Safari / browser».

## 1.12 · Двоение с Dewarp/LUT, питание второго адаптера

- **Двоение движущихся объектов на HDMI с LUT/Dewarp исправлено:** видеоядро
  дорисовывает кадр до конца (glFinish), прежде чем он уходит на экран.
- **Второй Wi-Fi адаптер** работает в режиме энергосбережения — меньше
  нагружает питание Pi (меньше предупреждений о низком напряжении).

## 1.11 · Видео на заставке, просмотр открывается сам

- **Фоновое видео на заставке:** любой загруженный ролик (Display → Splash
  screen) один раз подготавливается (H.264 до 1080p — как есть, 4K и другие
  кодеки — перекодируются в 1080p30) и крутится по кругу за заставкой — на
  HDMI, в браузерах и трансляциях. Кнопка включает и выключает его без Save.
- **Просмотр открывается сам при подключении к Wi-Fi:** DNS точки доступа
  отправляет проверки интернета телефонов (Apple, Google, Microsoft, Firefox,
  GNOME) на устройство, и оно показывает страницу просмотра как окно входа.
  Network → Access point → Open the viewer when a phone joins.

## 1.10 · Заставка без Dewarp

- Заставка с QR-кодом и своя картинка больше не проходят через Dewarp и LUT
  (не растягиваются); обработка применяется только к видео с очков, включая
  застывший последний кадр.

## 1.9 · Страница для зрителей, без двоения с LUT/Dewarp

- **Гости видят только картинку.** Если задан пароль, по обычному адресу
  открывается чистая страница просмотра: логотип, видео, статус. Настройки —
  по адресу `/admin` после входа; `/view` показывает владельцу то, что видят
  гости.
- Гости сами выбирают качество (Auto / Original / Light) и соединение
  (WebRTC / WebSocket); выбор хранится в их браузере. Три быстрых нажатия на
  логотип открывают `/admin`.
- **Двоение на HDMI:** экран удерживает три последних показанных кадра,
  чтобы видеоядро не рисовало в кадр, который ещё выводится.
- Менеджеры паролей сохраняют пароль под именем rdstreamer.

## 1.8 · Лёгкий поток для браузера

- **Light-поток для слабого Wi-Fi:** 720p, 30 к/с, 3.5 Мбит/с, ключевой кадр
  раз в секунду (против 11–25 Мбит/с у очков). Работает, только пока его
  кто-то смотрит.
- Streaming → Browser viewing → **Quality**: **Auto** (по умолчанию: оригинал,
  а при отставании больше 0.6 с или потерях больше 3 % — лёгкий поток),
  **Original**, **Light**. Статистика плеера показывает, какой поток идёт.

## 1.7 · Второй Wi-Fi адаптер, прогресс обновления, часы синхронизации

- **Второй USB Wi-Fi адаптер для интернета:** своя карточка на странице
  Network — подключение к сети (сканирование, пароль, 5 ГГц по разрешению),
  пока встроенный Wi-Fi держит точку доступа. Сохранение не перезапускает
  точку доступа; адаптер, вставленный позже, подключится сам. В строке
  состояния — «WiFi 2».
- **Прогресс обновления:** скачано МБ, скорость, оставшееся время; зависшая
  загрузка (меньше 1 КБ/с 20 с) прерывается с причиной и пробуется ещё раз.
  Установка показывает секунды и текущий шаг.
- **Sync Clock** (`/sync`, в меню Tools): время с миллисекундами, кадр и
  таймкод 24–60 к/с, полоса кадров, вспышка и метки — для синхронизации
  камер. Все телефоны и ноутбуки показывают одно и то же время устройства
  (измеряется по сети каждые 30 с). Можно ввести своё время и поправлять
  кнопками ±1 ч / ±1 мин / ±1 с; поправка хранится на устройстве. Экран не
  гаснет.
- _1.6 не была опубликована: её изменения вошли в 1.7._

## 1.5 · Уровень чёрного, версия вверху

- **Уровень чёрного с Dewarp/LUT:** блок обработки Pi отдаёт RGB в диапазоне
  16–235, и с обработкой чёрный становился серым. Шейдер растягивает его до
  полного диапазона — картинка совпадает с HDMI без обработки.
- **Версия в строке состояния;** становится оранжевой, когда доступна,
  скачана или ставится новая.
- Сканер каналов считает роутер с несколькими сетями как одно радио.
- iPhone, раздающий интернет по USB, показывается как телефон, а не Ethernet.

## 1.4 · Автообновление, сканер каналов

- **Обновления скачиваются сами** (проверка дважды в день) и проверяются;
  строка состояния показывает, что новая версия готова. С опцией **Install
  automatically** (выключена по умолчанию) ставится сама после 5 минут без
  видео, записи, трансляций и зрителей. Неудачная версия сама повторно не
  ставится.
- **Сканер каналов** сканирует с отдельного интерфейса рядом с точкой доступа
  (чип Pi не сканирует на вещающем интерфейсе), или со второго адаптера, если
  он вставлен.

## 1.3 · Обновления из веб-интерфейса

- **Свои подписанные обновления.** System → Updates и установщик доверяют
  ключу RDstreamer и ищут новые релизы в этом репозитории. Сборки с версией в
  названии получают подписанный `.deb` и `manifest.json`; без версии — это
  pre-release, устройства их не берут.
- Релиз публикуется только вместе с образом SD-карты.

## 1.2 · Питание, Wi-Fi, сканер, без зависаний HDMI

- **Строка состояния:** питание Pi (низкое напряжение сейчас или раньше,
  троттлинг), Wi-Fi (точка доступа с устройствами и их сигналом или
  подключённая сеть с сигналом), Ethernet или телефон, если трансляции идут
  через них.
- **Сканер каналов** на странице Network: загрузка каждого канала 2.4 ГГц,
  перекрытия, слышимые сети и самый свободный из 1, 6 и 11.
- **Замерзание HDMI:** декодер, который принимает кадры, но 2.5 с ничего не
  выдаёт, перезапускается; HDMI без кадров 3 с запускается заново.
- **Отставание в браузере на секунды:** буфер отправки ограничен 256 КБ;
  зритель, отставший больше чем на 0.25 с, перескакивает к ключевому кадру,
  плеер догоняет при отставании больше 0.8 с.

## 1.1 · LUT, Dewarp, превью

- **LUT для HDMI на видеоядре:** встроенные пресеты (film, warm, cool, teal &
  orange, punchy, vivid FPV, black & white, HLG → Rec.709), библиотека своих
  `.cube` (DJI D-Log / D-Log M / D-Cinelike, экспорты из Resolve), сила
  0–100 %, бесплатный набор LUT для скачивания.
- **Dewarp:** исправление «рыбьего глаза» и краёв, зум, смещения — в том же
  проходе видеоядра.
- **Processing: Speed** (720p, 60 к/с) или **Quality** (полный размер).
- **Живое превью** на Display → Image: браузер рисует картинку тем же
  шейдером, что и Pi; Before / Split / After.
- **HDMI восстанавливается сам,** если конвейер не запустился или сломался.

## 1.0 · Интерфейс, логотип, вентилятор Argon ONE

- **Корпус Argon ONE (V2) из коробки,** без скриптов Argon40 и `argononed`:
  - вентилятор по своей кривой температуры, настраивается в браузере
    (System → General → Cooling fan); кривая обязана дойти до 100 % к 75 °C;
  - кнопка питания: двойное нажатие — перезагрузка, удержание 3 с —
    выключение (запись сначала завершается);
  - отключение питания корпусом после выключения Pi;
  - необязательный «пинок» для вентиляторов, которые не стартуют медленно;
  - переход с `argononed` в один клик с переносом его кривой;
  - скорость вентилятора на странице Performance.
- **Новый вид:** тёмно-серый с оранжевым из логотипа RD, логотип в меню, на
  входе и на заставке HDMI, шрифт Rajdhani, строка состояния на каждой
  странице, палитра команд (Ctrl/⌘+K или /), нижняя панель с кнопкой записи
  на телефоне, картинка в плеере, пока нет видео.
- **Свои имена:** Wi-Fi `RDstreamer` (пароль `RDstreamer`), адрес
  `rdstreamer.local`, вход по SSH `rdstreamer` / `rdstreamer`, источник NDI/OMT
  `RDstreamer`.
- **Сборка на GitHub:** Actions → Build RDstreamer собирает пакет и образ
  SD-карты и публикует релиз.
